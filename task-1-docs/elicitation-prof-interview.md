# Elicitation Interview: Prof. Saurabh Tiwari

**Project:** Deepfake Detection Web App

**Technique:** Semi-structured stakeholder interview

**Purpose:** Clarify project scope, assessment expectations, verification, and user needs for an academic, non-commercial prototype in India.

## Interview questions

1. **Scope and acceptance — Requirements**

   Our current requirements include image, video, and audio detection, a browser extension, a WhatsApp channel, and moderation workflows. Which would you treat as the core deliverable, and which as optional or risky for our timeline?

2. **Definition of done — Validation**

   What would distinguish an excellent project from a merely passing one? How will you evaluate the SRS, working demo, design artifacts, and evidence of our development process?

3. **Process model — Planning**

   What development process do you expect us to follow and demonstrate: Agile/Scrum with sprints, an iterative approach, or a plan-driven approach? Do you expect user stories with acceptance criteria and a traceability matrix linking requirements to tests?

4. **Testing ML-based software — Verification**

   How should we test a system whose output is probabilistic? What combination of dataset metrics, failure-case analysis, and conventional unit, integration, and system testing would convince you that our test strategy is adequate?

   *Optional probe:* How should we set measurable acceptance criteria for false positives on compressed authentic media and for uncertain predictions?

5. **Project risk — Risk management**

   Which risk worries you most for a student team: model accuracy on real-world media, scope creep, integration complexity, or something else? What would you cut first if we fall behind?

6. **Maintainability and deployment — Deployment and maintenance**

   Detection models can become less reliable as generation techniques evolve. What level of deployment, CI/CD, model versioning, and documentation do you expect for this prototype?

7. **User stories — Elicitation**

   Imagine you are the user at the final demo. Describe two or three scenarios you would want to see from start to finish, and what you would consider a failure.

8. **Professor as an end user — Scenario**

   Suppose a clip of a public figure, or someone from the university, arrives in a WhatsApp group you are in, and people react as if it is real. Walk us through what you would do today to check it. What would you want our tool to tell you in the first minute, and what would make you stop trusting it?

9. **Consent and privacy — Data requirements**

   For a non-commercial student prototype that processes potentially identifiable media, what consent, retention, and sharing rules should we establish? What evidence would you expect that these rules are followed?

## Interviewer notes

Ask the main questions first and use the optional probe only if time permits. Request concrete examples when an answer is broad. Before ending, repeat back the agreed core scope and acceptance criteria so the professor can correct our interpretation.

Record decisions, unresolved questions, and follow-up actions separately from assumptions. Obtain permission before recording the interview or attributing quotations.
