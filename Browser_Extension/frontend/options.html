Detection provider settings

Connect BitMind or a compatible image-detection REST API.

Custom REST API connector

This connector supports common single-request HTTP POST APIs. It does not implement OAuth refresh, signed requests, or asynchronous job polling. Check your provider's API documentation before entering these values.

1. Endpoint and authentication

Example: {"X-Client-ID":"demo"}. Do not put Authorization or Content-Type here; configure authentication above.

2. Image request format

For Base64, multipart and raw-byte modes, the extension fetches URL images from the active webpage before uploading the bytes. This requires permission to access that image host. Manual uploads are supported in all four modes.

3. Map the provider response

Use dot paths for nested JSON and numeric indexes for arrays, for example result.label or predictions.0.score.

Comma-separated, case-insensitive labels. Unknown labels are reported as inconclusive; they are never silently treated as real.

Configuration and API credentials are stored in this Chrome profile.

Privacy and compatibility

Custom API credentials are stored in Chrome extension local storage. They are not exposed to webpage scripts, but this storage is not a hardware-backed secret vault. Images are transmitted to the selected provider. Use HTTPS endpoints; plain HTTP is permitted only for localhost development servers.
