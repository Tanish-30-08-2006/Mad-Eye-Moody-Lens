Task 2 — Elicitation Technique Selection
| Stakeholder                           | Technique                   | Justification                                                                                                                  |
| ------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| General Public User                   | **Survey**  | Large number of users, so a survey can quickly collect their usage patterns, concerns, and preferred features.                 |
| Journalist / Fact-Checker             | **Interview**               | Their verification workflow is detailed, so an interview can capture their specific needs and trust requirements.              |
| Social Media Moderator                | **Interview / Observation** | Observing or discussing their moderation workflow helps identify how they handle flagged or manipulated content.               |
| Platform Admin                        | **Brainstorming**           | The admin role is being designed for the system, so the team can brainstorm the dashboard, actions, and management needs.      |
| ML / Data Engineer                    | **Document Analysis**       | Technical requirements can be identified by reviewing deepfake detection research, models, and benchmarks.                     |
| Frontend / Backend Developer          | **Document Analysis**       | Existing technical documentation helps identify implementation constraints for the upload flow, dashboard, and extension.      |
| Dataset Provider / Research Community | **Document Analysis**       | Dataset documentation provides information about licensing, permitted use, and available data formats.                         |
| Browser Extension Store Reviewer      | **Document Analysis**       | Store policies define the permissions, privacy, and approval requirements for the extension.                                   |
| WhatsApp / Social Media Platform      | **Document Analysis**       | API and sharing documentation shows the limitations that may affect the share-link feature.                                    |
| Cloud / Hosting Provider              | **Document Analysis**       | Hosting documentation provides information about storage, processing, scalability, and infrastructure limits.                  |
| Subject of the Media                  | **Brainstorming**           | This stakeholder may not be directly reachable, so the team can identify privacy and ethical safeguards through brainstorming. |
| Legal / Compliance Body               | **Document Analysis**       | Laws and regulations provide the requirements related to privacy, data handling, and misinformation.                           |
| Course Instructor / Evaluator         | **Document Analysis**       | The project instructions define the academic requirements and expected deliverables.                                           |

This follows the stakeholder and technique mapping provided by P1.
